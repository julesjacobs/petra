# Target-directed checked capacities

Implementation proposal, not measured performance. The static audit found valid nonnegative, nonincreasing 0/1 potentials from the direct places of a target's NUPN unit and its ancestor units. Original initial marking and weighted pre/post arcs certify them; NUPN safety assertions are not trusted. Twelve competitor-only negative properties and two joint-unknown properties appear refutable this way; integrate/check actual solver outputs before counting gains.

Reuse the existing sparse Farkas proof language. For potential w>=0 with w*Delta<=0 and target row a*m>=b, choose alpha>=0 such that alpha*w>=a coordinatewise. The nonnegative place-row multipliers alpha*w-a plus one multiplier for the target row give lhs alpha*w*Delta<=0 and rhs b-alpha*w*m0. If rhs>0 this is an exact sparse Farkas contradiction. For an equality, also try (-a,-b). With 0/1 potentials alpha is the maximum positive target coefficient, provided every positive coefficient lies in the support. Negative coefficients are handled exactly, not dropped from the certificate. Use BigInt for signed arithmetic, including i64::MIN.

Linear::state_equation orders place rows first; for each target it adds the negated row first only if equality, then the positive row. Preserve sorted positive multiplier row IDs. Verify through the existing Rust sparse checker; independent Python checker rechecks original incidence without materializing a dense state-equation matrix. Root hardened this Python branch to explicit validation instead of assertions, including tests under -O.

Architectural scope: checked preprocessing for focused/symbolic original PNML pipelines, reusing source text already loaded. Metadata only proposes hints. Malformed/cyclic/dangling NUPN metadata must cause hint rejection/fallback, never an unsound negative or changed ordinary net semantics. Do not add a mandatory hints field to Problem or alter canonical JSON/net meanings. Charge discovery to the existing whole-property deadline/work limit, cap its share, then solve with the remaining budget. Preserve no-hint behavior and exact original proofs. Expose candidates/bounds for later token-flow use, but do not claim integration into flow before it exists.
