# Signed-threshold prototype decision gates

Registered before any signed-threshold corpus execution. The initial supplied
kernel tests representability and correctness, not automatic coverage. General
solver contribution remains the objective; serializability is an application.

1. Kernel: independently implemented Rust/Python checkers validate the same
   invariant schema against original weighted transitions and arbitrary linear
   targets. Test numerical upper/lower binary relations on an unbounded net,
   read guards, affine signed forms, integer extrema, schema mutations, reachable
   targets and transition changes. Differential SCC and finite-net exploration
   tests precede any performance experiment. Recompute all obligations initially;
   proof paths/dependency caching are future optimizations.
2. Discovery: implement a deterministic finite-pool full-rescan Houdini reference.
   Candidates arise from negations of unary/binary subsets of target and failed
   predecessor cubes. Restart from all initially admissible candidates when the
   pool grows. Declare caps and ordering in a frozen plan before corpus use.
   Unary-only is the first precision ablation. Deadline/work exhaustion gives
   Unknown. Supplied certificates and handwritten clauses never count as solver
   coverage. Separate candidate selection from evaluation optimization.
3. Development screen: all656ordinary slots,640imports,16unavailable, duplicates
   and failures retained. Compare native property verdicts only after bounded
   independent original-input checking. Preserve frozen strongest native,
   matched batched, full portable SMPT and VerifyPN evidence. Single local runs
   qualify mechanisms; repeated balanced single-core Linux runs establish cost.
   Linux measurement31728 must finish before any remote builds or measurements.
4. Research investment: evaluate complementary automatic coverage and total
   discovery+checking cost, then test any promising mechanism on a harder,
   preregistered development extension. The Pro suggestion of ten additional
   negatives across three families is infeasible on the current cohort with
   only8native Unknowns, including a known reachable query. Do not substitute a
   weaker baseline. No numeric publication-success threshold is adopted before
   the development extension and matching baseline qualification are fixed.
   Existing closed cases remain useful for comparing proof/discovery cost.
5. Optimization: dependency caching must return the same surviving clauses as
   full rescanning on identical finite candidate pools. Path certificates must
   revalidate every edge and cover all original obligations. State these as
   separate changes and freeze matched ablations. Phase indexing, extra semantic
   lemmas and new affine directions are not implicit in v1.

Reject the direction as the central mechanism if automatic proofs remain rare
while supplied examples succeed, gains stay confined to Boolean TokenRing cases,
arithmetic correlations force huge clause pools, or checking erases practical
benefit. Useful individual components may remain opt-in without a publication
claim. No change to the22reserved families or default portfolio in this phase.
