# Target closure optimization review

Coordinator reviewed the implementation against frozen solver-target-stubborn-v1. Only src/relaxed.rs, src/relaxed_stubborn_tests.rs and tests/relaxed.rs differ among the139 previously frozen source files. No change to portfolio scheduling, exact target-direction sums, necessary-enabler choice, queue fairness, marking deduplication, target acceptance, witness replay, method defaults or negative certification.

Early completion is sound: the selector tracks the unselected enabled transitions in the fixed marking. Every newly selected transition, including each complete-cache seed, updates this count. At zero, returning Full(AllEnabled) includes every enabled successor, whether or not the dependency closure has finished. This cannot remove a target-reaching trace. Incomplete direction caches still return full expansion before any seed use.

Dependency scan deduplication is sound: for a fixed marking, each indexed producer, consumer or reader list is immutable. The first traversal selects every member; later traversals of the same place and role cannot add a new member. Distinct roles use distinct bits. Flags are created anew for every select call and never survive to another marking. If the work budget or deadline interrupts a list, the entire selection returns full expansion, so a partial traversal cannot be mistaken for a completed closure on reuse. Pending insertion order is preserved for successful closures because skipped duplicates would only revisit previously selected actions.

The conservative invisible-mode path passes no TargetClosure, retaining its previous list traversal and work charging. Target mode adds a constant amount of work per dependency-list attempt to keep repeated skips resource-bounded. Diagnostics split selection failure by target evaluation, direction construction, seeding and closure; these phase counters still combine work-budget and deadline exhaustion.

The independent fixed-point closure test examines1536 seed/weighted-marking combinations and permits early-full only when all enabled actions belong to the reference closure. Other regressions cover different dependency roles, complete-only seeds, interrupted lists, fresh flags after marking changes, empty enabled sets and deadline fallback. Existing bounded exhaustive shortest-distance and weighted/read-arc tests remain relevant. Whole-engine fixed-width acceptance and token limits still cause Unknown; no complete mathematical reachability claim follows.
