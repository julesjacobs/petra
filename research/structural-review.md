# Structural algorithms and arithmetic review

Implemented marked-trap enumeration followed by rational state-equation refutation, and qualitative forward-support closure followed by an initially empty siphon invariant and rational state-equation refutation. Each refutation exports its place sets and a Farkas certificate for the strengthened target. The checkers independently check the structural arc conditions, initial marking, and the arithmetic contradiction. Enumeration is bounded; incomplete enumeration only loses refutations. Neither method establishes reachability.

`cargo test --test structural` passes eight tests, including 100 bounded weighted nets with read arcs and mixed signed linear target constraints checked against independently constructed reachable closures, 27 explicitly reachable target cases, malformed trap certificates, three-place traps, empty-siphon counterexamples, resource limits, and an unbounded independent-growth adversary. `cargo clippy --test structural -- -D warnings` passes.

Reviewed integer Fourier–Motzkin rounding and rational equality elimination. No soundness defect found. Integer original rows are integral by construction; gcd division with signed ceiling is valid over integer firing counts; nonnegative combinations and repeated normalization preserve necessity. Equality elimination selects two opposite necessary inequalities with opposite bounds and combines each remaining signed row with the appropriate equality side. Projected feasibility still returns unknown. Integer proof dependencies are earlier nodes and weights are checked nonnegative. The integer module's five tests pass.

Minor practical limitations: arithmetic row construction, some elimination-choice scans, and proof verification do not poll deadlines internally. Limits are therefore cooperative rather than hard wall-clock guarantees; the benchmark subprocess timeout remains necessary. The rational algorithm can retain duplicate zero-variable rows before generated-row deduplication, which can reduce coverage under row limits without affecting soundness. Native arithmetic and its native checker share some row construction/normalization logic, so the independent Python checker remains important.

Direct debug-build correctness checks on `e1_disjunct_0` and `e7_disjunct_0` both return unreachable with the checked traps `[0,7]` and `[0,6]`. These checks confirm the intended structural gap is addressed; they are not benchmark timing measurements.
The Python benchmark checker also independently accepts both exported e1/e7 structural refutations.
