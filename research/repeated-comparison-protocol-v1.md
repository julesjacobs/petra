# Repeated original-input comparison: protocol draft

Status: not launched and not a frozen execution plan. Finalize only after the
current Linux combined-portfolio comparison passes artifact audit. No reserved
evaluation family is selected, imported or measured by this protocol.

The next comparison should establish budget sensitivity and repeatability before
claiming an advantage or consuming the reserved evaluation set. Use the existing
176-property general-development-v3 original PNML/XML cohort, including every
failure and all 175 distinct ordered-branch representatives. Report both counts;
use the distinct representatives for aggregate comparisons that assume distinct
queries. This remains development evidence.

Compare four frozen configurations: native portfolio-reduced, the frozen existing
portfolio-batched solver, unrestricted VerifyPN defaults, and the qualified SMPT
MCC portable configuration. Retain the exact executable, source, tool-dependency,
runner and checker identities from the audited combined comparison. The optional
frontier count planner is not eligible without evidence that it improves the
combined solver. Keep native random seeds fixed: repetition here measures runtime
variation rather than introducing different algorithms.

Use five- and thirty-second invocation budgets, three independent blocks per
budget, one run per property/method per block: 4,224 original-property invocations.
Give each block a separately frozen query-order seed so method-order rotation is
not repeated identically across all measurements. Alternate budget order between
blocks; record the complete block and invocation order before execution. A failure
must remain a failure; any later replacement run needs a separate registration.

Retain CPU 8 affinity, enforced 2 GiB memory, current process-tree isolation and
performance-counter collection. Only one solver invocation or independent checker
runs at a time on that host. No builds, deployments or bulk transfers during a
measurement block. Verify all pins and tool capability before launch and preserve
exact detached-process identities. Observation failures never trigger a restart.

Native answer validation remains bounded and outside solver timing. Report solver
cost and independent validation cost separately. External verdicts are tool-reported
unless independently checked; disagreement triggers investigation, not majority
voting. Preserve startup costs because these are original-input end-to-end solver
invocations. Report timeout, out-of-memory, crash, invalid-answer, validation-timeout
and unsupported-input counts distinctly.

Report solved sets for every block and budget, paired gains/losses, answer
agreement, per-query timing variation, memory and instruction counts, and checking
cost. Timing comparisons must state their common-solved selection; supplement them
with a fixed timeout-penalized metric over the full cohort. Do not turn a five-second
lead that disappears at thirty seconds into a general superiority claim. Three
blocks provide a repeatability check, not a precise population-level uncertainty
estimate for a diverse benchmark universe.

The current protocol is a concrete next evaluation step. It does not establish
algorithmic novelty, substantial advantage, generalization, or publication readiness.
The separate reserved-evaluation-v2 selection remains untouched until candidate
and competitor configurations, reporting rules and an exposure audit are frozen.
